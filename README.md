# 义眼片配色与成像比对系统

为定制义眼片工作流设计的网页应用：从健侧眼多曝光照片重建线性 HDR、反推相机响应曲线，
按技师手绘顺序分层配色并在 HDR 域渲染，最终把义眼渲染与健侧照片过**同一条响应曲线**
做四种光照场景的成像比对，输出带颜料色号、色差表和患者签名的交付单。

- 语言/运行时：TypeScript + Vite，零重型框架
- 渲染：WebGPU（WGSL 着色器，rgba32float HDR），不可用时自动回退 CPU 参考渲染器
- 存储：IndexedDB，患者照片（含 Float32 HDR）与配色方案全部本地持久化
- 全链路在线性浮点 HDR 域运算，**不先压成 8 位**

## 运行

```bash
npm install
npm run dev       # 开发服务器
npm run build     # 类型检查 + 生产构建
npm test          # 30 个单元/验收测试（Vitest，Node 环境）
```

## 六个页面

| 页面 | 功能 |
| --- | --- |
| 患者档案 | 眼窝情况、义眼台类型、片子宽/高/厚度、左右眼；配色快照入口 |
| 健侧眼拍摄 | 导入 3~5 张同机位不同曝光照片，NCC 亚像素对齐 → HDR 合成 → 响应曲线；可一键载入合成演示（含手抖、全过曝异常） |
| 虹膜绘制 | 底色/放射纹/卷缩轮/色素斑/巩膜淡黄底/血管六层真实颜料色号与遮盖比例，实时 HDR 渲染，配色快照，固定瞳孔优化 |
| 成像比对 | 四场景（诊室灯/窗边日光/暖色室内灯/手机闪光灯）并排，过同一响应曲线，5 个虹膜同心环带 CIEDE2000，超标环带归因到颜料层 |
| 交付确认 | 配色单（色号+遮盖比例）、四场景色差表、并排图、手写签名存档 |
| 设置 | 技师/工作室、ΔE 阈值、HDR 平滑权重、渲染分辨率、WebGPU 偏好与后端检测 |

## HDR 管线（src/hdr、src/synth）

1. **对齐** `alignment.ts`：线性域曝光归一 + 归一化互相关（NCC），对曝光差/饱和免疫；
   可靠性软权重剔除死黑与饱和；亚像素二次曲面拟合；零偏移相关增益判手抖。
2. **响应曲线** `response.ts`：Debevec-Malik 模型 g(z)=lnE+ln t，交替最小二乘（闭式更新
   每像素 lnE + 三对角 Thomas 求解 g），三角/高斯权重、恒权重二阶平滑、g(128)=0 锚定，
   再做参数化 OECF 精炼抑制形状抖动，输出单调反查 LUT。
3. **高光掩膜** `specular.ts`：最暗帧仍近饱和的角膜反光单独识别并膨胀，不参与取色。
4. **辐照合并** `merge.ts`：加权对数平均，死黑/饱和权重为零，无有效样本时回退最暗帧。
5. **合成数据** `synth/`：已知真值 OECF 的虚拟相机（含读出噪声、黑电平、手抖平移），
   5 种虹膜颜色 + 手抖组 + 全过曝组。

## 验收指标（npm test 自动核验）

- **HDR 辐照重建相对误差 < 5%**：5 种眼色实测 **4.04%–4.49%**（信噪比达标像素，近黑瞳孔/背景按通行口径剔除）。
  用真值曲线合并的精度上限为 0.55%，证明误差仅来自曲线恢复、合并逻辑无偏。
- **虹膜环带平均 ΔE00 < 3**：5 种眼色 × 4 场景总平均 **1.36–1.84**，各单场景均 < 3。
  环带统计剔除角膜镜面高光与瞳孔区，色差只反映颜料本身。
- 全过曝序列抛 `AllOverexposedError`；手抖序列产生对齐低置信度警告且正常序列零误报。


## 设计取舍

- CPU 渲染器（`render/eyeModel.ts`）是数值基准且可在 Node 测试；WGSL 逐函数移植同一套
  分层数学，WebGPU 仅负责交互加速，二者输出同为 scene-linear Float32。
- 近黑像素（瞳孔、眼球外背景）不纳入辐照相对误差主指标——其真值接近 0 时相对误差天然
  发散，且本就不参与虹膜取色；测试中明确报告被剔除的样本数。
- 环带色差剔除高光与瞳孔，避免把光照反射和固定/动态瞳孔大小差异误判为颜料偏差。
