# 瞳色工坊 · 义眼片 HDR 配色与成像比对系统

给定制义眼片技师用的网页端配色 / 成像比对工具。TypeScript + WebGPU(WGSL) + IndexedDB，
纯本地运行，不上传患者照片。核心是一条**不能在中途压成 8bit 的线性 HDR 成像链**：

```
3–5 张不同曝光 LDR
   └─ MTB 中位数阈值位图自动对齐（含手抖组验证）
        └─ Debevec–Malik 反演相机响应曲线 g(Z)=ln曝光量（曲线可画）
             └─ 加权对数域 HDR 合成（Float32 线性辐照度）
                  └─ 角膜高光过曝区检测 + 掩膜剔除（不当作虹膜颜色）
                       └─ 八环带取色 → 闭环拟合分层颜料配方
                            └─ 线性 HDR 渲染义眼片（WebGPU rgba16float / CPU 参考）
                                 └─ WB × 曝光 × 同一条响应曲线编码
                                      └─ 与健侧照片同条件比对 · CIEDE2000 环带色差
```

## 验收指标（`npm run verify`）

合成 4 种不同虹膜颜色的健侧眼 + 多曝光序列，另掺 **1 组手抖未对齐** 与 **1 组全部过曝**。
最近一次结果见 [`verify-report.json`](./verify-report.json)：

- HDR 合成辐照度 vs 造图真值，虹膜 ROI 平均相对误差 **≈0.8%**（要求 < 5%）
- 渲染结果过同一响应曲线后 vs 健侧照片，八环带平均 **ΔE00 ≈ 0.75**（要求 < 3）
- 手抖组位移正确解算、MTB 失配显著下降
- 全过曝组被质量门限正确拦截，拒绝给出配色结论

```bash
npm install
npm run verify      # 无头复算两条硬指标，非 0 退出即不达标
npm run dev         # 启动应用（默认 http://127.0.0.1:5173）
npm run build       # 类型检查 + 生产构建
```

应用首次打开会自动在 IndexedDB 生成 6 位合成患者（深棕 / 琥珀 / 蓝灰 / 绿褐 / 手抖 / 全过曝）。
在「设置与自检」页也可直接在浏览器内重跑端到端自检、重新生成或清空演示数据。

## 六个页面

1. **患者档案** — 眼窝情况、义眼台类型、片子直径/厚度、左右眼别（术眼/健侧对侧关系明确），每次调整留存配色快照，可从任意快照或历史交付单「下一副从这份起步」。
2. **健侧眼拍摄** — 导入同一机位 3–5 张不同曝光照片；MTB 对齐、Debevec 曲线反演并画曲线、HDR 线性预览、角膜高光掩膜、对齐/饱和率质量判定。
3. **虹膜绘制** — 底色（八环带真实颜料配比）、放射纹、卷缩轮、色素斑、巩膜分区淡黄底与血管、最上层透明角膜凸面；WebGPU 优先（rgba16float HDR 目标 + 响应曲线 LUT 后处理），不可用时自动回退同源 CPU 参考渲染。
4. **成像比对** — 两侧走同一条响应曲线/曝光/WB；诊室灯、窗边日光、暖色室内灯、手机闪光灯四场景；环带 ΔE 条形图、超标环带、按层归因的调色建议；四场景固定瞳孔尺寸 RMS/minimax 优化与曲线。
5. **交付确认** — 分层颜料色号 + Colour Index 通用名 + 有效遮盖比例的配色单、并排比对图、四场景色差表、鼠标/触屏签名，签字后存档 IndexedDB。
6. **设置与自检** — ΔE/HDR 阈值、渲染后端、工作室信息、浏览器内数值自检、数据重置。

## 颜料色号

`src/core/pigments.ts` 中每个颜料给出工作室色号（W-/Y-/BR-/B-…）与真实 **Colour Index** 颜料通用名
（PW6、PBr7、PB29、PG17…）。配比在线性反射率空间按着色力加权混合，配比由
Lab/ΔE00 上的组合枚举 + 单纯形坐标搜索反解。

> 说明：色号体系是工作室内部编号，Colour Index 名称与颜料本身对应真实；不冒充任何厂商商业色号。

## 目录结构

```
src/core/        纯 TS、Node 与浏览器共用的数值核心（颜色科学/HDR/拟合/合成/瞳孔）
src/webgpu/      WGSL + WebGPU HDR 渲染器（失败自动回退 CPU）
src/browser/     Canvas / IndexedDB 上下文等浏览器适配
src/data/        IndexedDB 仓储、首次播种、序列处理服务
src/pages/       六个页面
src/ui/          DOM helper、SVG 图表
scripts/verify.ts  无头验收脚本
```

## 重要实现约定

- **尺度归一化**：Debevec 曲线带整体尺度自由度。拟合前按虹膜中位亮度把 HDR 归一到规范尺度，
  曝光标量 `gain` 与该归一化 HDR 对应并随方案持久化（`scheme.fitGain`），保证任意曲线锚点下结果一致。
- **高光不参与取色**：合成时的角膜高光过曝团块经连通域 + 上半部先验 + 膨胀形成掩膜，环带统计与拟合一律剔除。
- **指标同源**：页面上的 ΔE 与 `npm run verify` 都调用 `src/core/matching.ts` 的同一份实现；
  WebGPU 负责实时画面，质控数值始终以 CPU 参考链路为准。
- 瞳孔的场景估计使用照度→适应亮度 + Watson–Yekimov 型幂律，并用拍摄实测直径标定整体偏移。
